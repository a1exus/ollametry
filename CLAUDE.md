# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. Operating rules are in [`AGENTS.md`](AGENTS.md); user-facing docs are [`README.md`](README.md) and [`docs/`](docs/).

## Project overview

ollametry is a Go reverse proxy in front of a host-installed Ollama (macOS app, not Docker). It relays every request unchanged and records OpenTelemetry metrics from the usage stats inside Ollama's responses, plus gauges from polling `/api/ps` and `/api/tags`. It exports OTLP/HTTP to `otel-lgtm` from `~/opt/grafana` by joining that stack's `grafana_default` network. It also serves the same metrics at `/metrics` on the admin listener, which makes it an Ollama Prometheus exporter (`OLLAMETRY_PROMETHEUS`, default on). Module: `github.com/a1exus/ollametry`.

## Request flow

1. `ServeHTTP` matches the route. For inference routes it buffers the body up to `MaxInspectBytes` to read `model` (larger bodies: prefix + rest via `MultiReader`, model from a token walk of the prefix).
2. `rewrite` sets the upstream URL and `X-Forwarded-*`, and drops `Accept-Encoding` on inference routes so the transport negotiates and transparently decodes gzip.
3. `modifyResponse` picks the `Format` from `Content-Type` and wraps the body in `tapBody`, which feeds the `Framer` → `Decoder` as bytes are relayed. `FlushInterval: -1` flushes every write.
4. After `ReverseProxy.ServeHTTP` returns (or panics with `http.ErrAbortHandler`, recovered and re-raised), `finish` records metrics with `context.WithoutCancel`.

## Verified facts and gotchas

Verified against Ollama 0.40.13 and `grafana/otel-lgtm:0.39.0` (Prometheus 3.15.1, Grafana 13.3.0).

- **Reasoning comes first**: native `thinking`, OpenAI `reasoning`, Anthropic `thinking_delta`, Responses `reasoning_summary_text.delta`. Time to first token counts them.
- **Cached tokens**: native and OpenAI report input including cached (`prompt_eval_count` 21, cached 20); Anthropic reports them apart (`input_tokens` 1 + `cache_read_input_tokens` 20). `Result.InputTokens` always includes cached.
- **Anthropic `message_start` usage is provisional** (6 input tokens); the final `message_delta` holds the real counts. Usage fields are pointers so partial updates work.
- **`/v1/completions` streams repeat a zeroed `usage`** on every chunk; only non-zero usage is taken.
- **OpenAI streams have no usage** unless the client sends `stream_options.include_usage`; when they do, the final chunk also has llama.cpp `timings` (`predicted_ms`), used for time per output token.
- **Ollama's `Host` check accepts `host.docker.internal`**; `SetURL` sends the upstream host. Docker Desktop routes `host.docker.internal` to the host loopback, where Ollama listens.
- **OTLP → Prometheus names**: `.` → `_`, unit suffixes added (`_seconds`, `_bytes`), counters get `_total`, `{token}`-style units add nothing. A unit of `"1"` adds `_ratio`, which is why `ollama.up` has no unit.
- **OTLP counters have no start point in Prometheus**: the first export of a series is its baseline, so a model's first request is missing from `rate()`/`increase()`.
- **Series from a replaced container linger 5 minutes** (no staleness markers for OTLP) with a different `service_version`; dashboard queries aggregate by model name, never `count()` raw series.
- **CodeQL `go/log-injection` is a false positive here**: slog's JSON and text handlers escape control characters, so client values cannot forge lines (`TestProxyLogsCannotBeForged`). What matters is size: log the method via `logMethod`, paths via `logPath`, models via `sanitizeModel`.
- **`/metrics` and OTLP share one meter provider**, so views and the cardinality limit apply to both and the series match. `autoexport` builds a single reader (no `otlp,prometheus` list), which is why the Prometheus reader is ollametry's own. `promtool check metrics` flags only `go_goroutine_count`, a name from the OTel Go runtime conventions.
- **ollametry sets no `service.instance.id`**, so Prometheus has no `instance` label: a restart of the same version continues the same series, and a new version shows up as a separate series by `service_version`. Tests and queries compare series by their full label set and never sum across them.
- **Gauges of an unloaded model linger the same 5 minutes** (the SDK stops reporting unobserved series, Prometheus keeps the last sample). Model panels filter with `X and (time() - timestamp(X) < 45)`, three export intervals. For the same reason `ollama.up` has no attributes (up and down are one series) and the version lives on `ollama.build.info`.
- **`gen_ai.request.model` only names models Ollama has** (`Poller.KnownModel` via `proxy.Config.KnownModel`); others become `_OTHER`. `ollama.inference.active` is cumulative, so every distinct name would hold a series forever.
- **Allocations are the performance gate, not timings**: `TestProxyAllocationsPerRecord` bounds allocations per streamed record (2.0, 3.8 under `-race`; `raceEnabled` comes from `race_on_test.go` / `race_off_test.go`). ReverseProxy copies through a pooled 32 KiB buffer (`copyBuffers`); without it every request allocated one (−53 % memory per request, benchstat p=0.000).
- **`http.Server.Close` does not wait for handlers**: shutdown calls `Proxy.Wait` before the final flush, and tests use it (`waitRecorded`) because `finish` records several metrics in turn.
- **httpconv appends its default options after the caller's**, so bucket overrides must be SDK Views (`telemetry.httpDurationView`).
- **The dashboard is file-provisioned by `~/opt/grafana`** (`make dashboards` there copies `deploy/grafana/*.json`). Grafana refuses UI and API saves of provisioned dashboards, so edit the JSON here and re-sync.
- **`govulncheck` below v1.9 panics on Go 1.27** (`unexpected expr: *ast.KeyValueExpr`).
- **Ollama decodes requests with `encoding/json`**: keys match case-insensitively (`"Model"` works) and the last duplicate wins. `modelFromPrefix` (bodies over `MaxInspectBytes`) mirrors this; `FuzzModelFromPrefix` checks it against `encoding/json` on every valid body.

## CI and releases

| Workflow | Runs on | Does |
|---|---|---|
| `ci.yml` | PRs, pushes to `main` | Matrix legs, each one `make` target: `ci-lint` (tidy-check, versions-check, lint, vuln, lint-ci, dashboard-check, rules-check, notices-check), `test-unit`, `cover` (unit + integration). E2E is local only (`make e2e`, `make e2e-hermetic`): it needs a real Ollama and multi-GB images, and the integration tests already cover the assembled binary and OTLP on every PR. Caches are bind-mounted dirs (`CACHE_GOMOD`, `CACHE_GOBUILD`, `CACHE_GOLANGCI`) kept by `actions/cache`, saved only on pushes to `main`. Multi-arch image build without QEMU and a smoke test without Ollama; dependency review on PRs |
| `fuzz.yml` | nightly, manual | `make fuzz` per target in parallel, 10 min each; failing inputs uploaded. Not a PR gate: PRs replay the corpus via `make test` |
| `codeql.yml` | PRs, `main`, weekly | CodeQL `security-and-quality` for Go (`GOTOOLCHAIN=auto` for the go.mod version) |
| `scorecard.yml` | `main`, weekly | OpenSSF Scorecard, published for the README badge |
| `release.yml` | tags `vX.Y.Z` | GHCR image (amd64, arm64) with SBOM and provenance, attestation; binary archives for darwin and linux (`make dist`) with attestation; GitHub release from the CHANGELOG section with the archives and `SHA256SUMS` (fails if the section is missing). Never run yet: the first tag is its first test |

Every action is pinned to a commit SHA with the version in a comment, chosen at least 14 days after release; Dependabot keeps them current with the same 14-day cooldown. Dependabot also watches Go modules, the Dockerfile and `test/e2e/compose.yaml`; it cannot read the Makefile's tool versions (`*_VERSION`), which are updated by hand. The Go version appears in `go.mod`, the Makefile and the Dockerfile; `make versions-check` keeps them equal. Workflows have `contents: read` (or none) at the top and grant more per job, each with a comment; `make lint-ci` (actionlint, zizmor) enforces this locally and in CI.

## Common commands

```sh
make check              # lint, lint-ci, unit + integration tests, vuln (CI runs the same)
make up && make health  # build, run, verify against the real Ollama
make smoke MODEL=granite4.2:8b
make e2e                # E2E against the running stack (after make up)
make e2e-hermetic       # E2E on a throwaway Ollama + otel-lgtm stack (local only)
make fuzz FUZZTIME=2m   # fuzz framer, decoders, model extraction (nightly in CI)
make -C ~/opt/grafana dashboards   # provision the dashboard
```

Inspect exported series without Grafana credentials:

```sh
docker exec otel-lgtm curl -s -G localhost:9090/api/v1/query --data-urlencode 'query=ollama_up'
```
