## [Unreleased]

### Added

- Prometheus exporter: `/metrics` on the admin listener (`:11436`) serves every metric in the Prometheus text format, alongside the OTLP push and from the same meter provider, so names, labels, views and limits match. On by default; `OLLAMETRY_PROMETHEUS=false` turns it off. Documented in `docs/prometheus.md`, including running without otel-lgtm.
- Three test layers: unit (no build tag), integration (`-tags integration`: the proxy and poller against a fake Ollama, and the whole binary exporting OTLP/HTTP to a fake collector) and end-to-end (`test/e2e`, `-tags e2e`: requests through the container to a real Ollama in every API family, checked in otel-lgtm's Prometheus). `make test-unit`, `make test-integration`, `make e2e` (running stack), `make e2e-hermetic` (throwaway stack from `test/e2e/compose.yaml`). E2E runs locally only.
- Nightly fuzzing workflow (`fuzz.yml`), 10 minutes per target in parallel, uploading failing inputs.
- `THIRD_PARTY_NOTICES.md`: licenses of everything distributed with ollametry (Go modules, generated by `make notices` with go-licenses and checked in CI; Go runtime; distroless base image) and of the services, tools and actions it uses. The image ships it with `LICENSE` in `/usr/share/doc/ollametry/`.
- `ollama.build.info` gauge carrying `ollama.version`; `ollama.up` no longer has attributes, so up and down are one series.

- Transparent reverse proxy for Ollama (`ollametry`) that relays requests and streams unchanged, flushes every write, and cancels the upstream request when the client hangs up.
- Response decoding for Ollama's native API (`/api/generate`, `/api/chat`, `/api/embed`, `/api/embeddings`), the OpenAI-compatible API (`/v1/chat/completions`, `/v1/completions`, `/v1/embeddings`), the Anthropic Messages API (`/v1/messages`) and the Responses API (`/v1/responses`), streamed or not.
- OpenTelemetry GenAI metrics: `gen_ai.client.operation.duration`, `gen_ai.client.token.usage`, `gen_ai.server.time_to_first_token`, `gen_ai.server.time_per_output_token`; plus `ollama.prompt.cached_tokens`, `ollama.model.load.duration`, `ollama.prompt.eval.duration`, `ollama.inference.active`.
- HTTP server metrics for every proxied route: `http.server.request.duration`, `http.server.active_requests`, with low-cardinality `http.route` templates.
- `error.type` classification: HTTP status, API error types reported inside a stream, `incomplete`, `canceled`, `upstream_error`.
- Poller for `/api/version`, `/api/ps` and `/api/tags`: `ollama.up`, per-model memory, GPU memory, context length and keep-alive remaining, installed model count and disk use.
- Configuration by flags and `OLLAMETRY_*` variables; exporter configured by standard `OTEL_*` variables (OTLP by default, Prometheus or console optional); Go runtime metrics.
- `/livez` and `/readyz` on a separate admin listener; `ollametry healthcheck` subcommand for the distroless image.
- Distroless, non-root, read-only container on the `grafana_default` network, ports bound to `127.0.0.1` (11435 proxy, 11436 admin).
- Base images (`golang`, `distroless/static`) pinned to multi-arch index digests, with literal tags that Dependabot can update.
- Grafana dashboard `deploy/grafana/ollametry.json`, provisioned by `~/opt/grafana` (`make dashboards`).
- Makefile running Go 1.27.3, golangci-lint v2.15.0 and govulncheck v1.9.0 in containers: `test`, `lint`, `fmt`, `vuln`, `check`, `cover`, `up`, `down`, `health`, `smoke`.
- Tests against responses recorded from Ollama 0.40.13.
- Fuzz tests for the response framer, the decoders and request-body model extraction; `make fuzz` (`FUZZTIME`, default 30s per target), 20s per target in CI. Found that model extraction from oversized request bodies missed `"Model"` and duplicate keys; it now resolves keys like `encoding/json` and Ollama: case-insensitively, last one wins.
- Tests for the meter provider: histogram buckets (including the `http.server.request.duration` view), resource and `OTEL_SERVICE_NAME`, cardinality limit, Go runtime metrics.
- `README.md`, `AGENTS.md`, `CLAUDE.md`, `CHANGELOG.md`.
- MIT license (`LICENSE`), also declared on the image as `org.opencontainers.image.licenses`.
- GitHub Actions: CI (`make` lint, race tests with coverage, govulncheck, workflow lint, multi-arch image build and smoke test, dependency review), CodeQL, OpenSSF Scorecard, and a tag-triggered release publishing the image to GHCR with SBOM, provenance and attestation. All actions pinned to commit SHAs.
- `make lint-ci` (actionlint 1.7.12, zizmor 1.30.1), now part of `make check`.
- Dependabot for Go modules, GitHub Actions and the base image, weekly with a 14-day cooldown.
- `SECURITY.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), issue forms, pull request template, `CODEOWNERS`, `.editorconfig`; README badges.

### Changed

- Fuzzing no longer runs on pull requests: random exploration made an unrelated change fail when it found something, and `make test` already replays the corpus. CI legs are now lint and scan, unit tests, integration tests (with coverage) and E2E.
- `docker-compose.yml` renamed to `compose.yaml`; the service is never pulled (`pull_policy: build`) and is limited to 256 processes.
- Makefile lifecycle targets wrap `docker compose` one to one: `up` (`up -d --build --wait`), `down`, `start`, `stop`, `restart`, `build`, `rebuild`, `clean`, `ps` (`--all`), `logs` (`--follow`, `TAIL`), `top`, `images`.
- Dockerfile fails on any build-check warning (`# check=error=true`) and copies the binary with `COPY --link`.
- CI runs lint and scan, test and fuzz as parallel matrix legs with module, build and lint caches (`actions/cache`, saved only from `main`); new `make tidy-check`, `make dashboard-check` and `make ci-lint`; `make check` also validates the dashboard. Image builds no longer set up QEMU, which the cross-compiling Dockerfile never used.
- README is now an overview with a table of contents; details moved to `docs/` (clients, metrics, configuration, operations with troubleshooting, development, releases).

### Fixed

- `ollama.up` kept reading 1 for about 5 minutes after Ollama stopped: up and down were separate series.
- Dashboard model panels showed unloaded models for about 5 minutes; they now ignore samples older than 45 s.
- Unknown model names in requests created a `gen_ai.request.model` series each, permanently for `ollama.inference.active`; they are now recorded as `_OTHER`.
- Embeddings recorded an output token usage of 0.
- Protocol upgrades (`101 Switching Protocols`) failed with 502.
- Requests cut off by a shutdown timeout lost their metrics: shutdown now waits for handlers before the final flush.
- A poll interrupted by shutdown reported Ollama as down.
